# 无障碍实现与验证

目标为 [WCAG 2.2](https://www.w3.org/TR/WCAG22/) A / AA，范围是网站首页、工具箱入口及浏览器内各工具的操作界面。自动扫描通过不能代替完整的人工合规评估；当前不发布「全站已获 WCAG 认证」的声明。

| 色彩 | 加深浅色说明文字、占位提示与状态文字；修复深色继承；增强输入边界、焦点和成功/错误颜色 | 1.4.3、1.4.11 |
| 键盘导航 | 首个 Tab 可到达「跳到主要内容」；工具导航聚焦新标题；标签和下拉选项保留方向键操作；下拉菜单展开时背景 inert，关闭后恢复；弹窗关闭后返回打开位置 | 2.1.1、2.1.2、2.4.1、2.4.3、2.4.7 |

无障碍之外，同时增加内存草稿保护：内容存在时点击链接离开工具箱先确认；刷新或关闭使用浏览器原生离开提示。取消后保留内容，未将文件或正文写入持久存储。浏览器返回/前进等 Next.js 客户端历史导航不承诺都能被此提示拦截；需要的结果仍应下载，不能把提示当成自动保存。

## 自动验证

在仓库根目录运行：

```sh
pnpm --filter @var/web exec playwright test e2e/accessibility.spec.ts
```

测试在生产静态构建上运行，使用 axe-core 的 `wcag2a`、`wcag2aa`、`wcag21a`、`wcag21aa`、`wcag22aa` 规则，包含：

- 首页、工具入口和全部子工具，浅色/深色两种主题。
- 所有文件转换模式及展开设置；文本整理与批量文本结果、表格处理/对比结果、文件转换结果、重命名错误和 PDF 页码/水印。
- 文本设置、全局文件任务和 PDF 预览弹窗；关闭后的焦点返回。
- 键盘跳过导航、打开工具、标签方向键与 PDF 排序；离开/刷新提示的取消路径。
- 320 CSS px 下的重排与 WCAG 文本间距覆盖，及窄屏导入后的界面和底部按钮可达性。
- 640×400、320×256 CSS px 短视口下，帮助、统计、设置、文件任务与 PDF 预览的焦点可见性；40 列长表头选项的键盘滚动；强制颜色模拟中的焦点轮廓。检查会等待弹窗和主题完成绘制，不靠移除断言避开失败。

常规 `pnpm test:e2e` 也会运行这些检查。不要为了通过测试屏蔽规则、排除业务控件或移除失败断言；应修复对应页面状态。

WebKit 和 Firefox 使用独立配置按需验收，默认 Chromium 回归不因此增加浏览器安装要求：

```sh
pnpm --filter @var/web exec playwright install webkit
pnpm --filter @var/web exec playwright test --config=playwright.cross-browser.config.ts --project=webkit accessibility.spec.ts accessibility-extended.spec.ts
```

在 macOS 的默认键盘偏好下，WebKit 的链接遍历使用 Option–Tab，参照 [Apple 的 Safari 快捷键说明](https://support.apple.com/en-ie/guide/safari/cpsh003/27.0/mac/27)。通用按钮在点击时明确取得焦点，保证没有启用鼠标点击聚焦的浏览器也能恢复弹窗打开位置。

WebKit 引擎回归不等于真实 Safari 或 iPhone 验收。当前下载的 Firefox 测试驱动两次启动均报告 `Could not find profile folder`，包括更换临时目录后的尝试；未能进入页面，Firefox 功能验收仍未完成。

## 仍需人工验证的范围

- VoiceOver / NVDA 的真实朗读顺序、重复或遗漏播报；自动识别出 live region 不等于实际读屏体验已验证。
- 真实 Safari、Firefox、真实手机，浏览器 200% 文本放大、400% 缩放和操作系统高对比度下的完整任务流程。短视口与强制颜色模拟不能取代这些人工测试。
- 用户导入的任意复杂内容及生成的 PDF / Word 的文档标签和阅读顺序。本轮针对操作界面，不把图片型 PDF 宣称为可选择文字或无障碍文档。
- 当前没有音视频、登录认证、支付或验证码；相关成功准则没有对应流程。以后加入这些功能时需要重新评估。

具体本轮命令结果见 [CHECKS.md](./CHECKS.md)。
